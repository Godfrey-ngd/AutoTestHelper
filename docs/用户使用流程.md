# AutoTestDesign 使用流程

## 概述

AutoTestDesign 是一个 AI 驱动的测试用例设计工具，基于 ISTQB / ISO 29119-4 标准。它从需求规格出发，通过 LLM + 规则引擎自动生成结构化的黑盒/白盒测试用例。

**访问地址：** http://localhost:8501

---

## 完整工作流

```
创建项目 → 导入需求 → 结构化解析 → 风险评估 → 覆盖项管理 → 策略配置 → 生成用例 → 审查导出
```

---

## 1. 创建 / 加载项目

**位置：** 左侧边栏

- **新建项目：** 展开 "New project"，输入项目名称和目标应用描述，点击 "Create project"
- **加载项目：** 展开 "Open project"，从下拉列表选择已有项目，点击 "Load project"

所有操作自动持久化到 `data/projects/` 目录。

---

## 2. 导入需求（Import 标签页）

支持三种导入方式：

| 方式 | 说明 |
|------|------|
| **Paste** | 粘贴 CSV 格式（`REQ-001,描述`）或纯文本需求 |
| **Structured Form** | 逐条填写需求 ID、标题、结构化字段（输入项、数据范围、条件、预期行为） |
| **Sample login requirements** | 使用预设的登录模块需求（7条）快速体验 |

导入后可选择：
- **Import only** — 仅解析导入，不调用 LLM
- **Import + Structure** — 导入后自动调用 LLM 结构化解析
- **Run full pipeline** — 一键执行完整管线（导入→结构化→风险评估→生成用例）

---

## 3. 结构化解析

需求导入后，系统自动提取结构化字段：
- **Inputs** — 输入字段（如 username, password）
- **Data Ranges** — 数据范围（如 3-20 字符）
- **Conditions** — 前置条件（如 counter >= 3）
- **Expected Actions** — 预期行为

支持 LLM 解析和规则引擎回退两种模式。

---

## 4. 风险评估（Risk 标签页）

### 可配置权重

| 维度 | 默认权重 | 说明 |
|------|----------|------|
| Business Impact | 40% | 失效对安全、数据、营收的影响 |
| Failure Probability | 35% | 复杂度、依赖、历史缺陷导致的失效概率 |
| Detectability | 25% | 失效后是否容易被发现 |

### 风险等级

| 等级 | 分数 | 颜色标识 |
|------|------|----------|
| H (High) | ≥80 | 红色 |
| M (Medium) | 50-79 | 黄色 |
| L (Low) | <50 | 绿色 |

点击 "Assess risks" 执行评估。权重滑块调整后可点击 "Re-assess with new weights" 重新评估。

---

## 5. 覆盖项管理（Coverage 标签页）

### 查看覆盖项
管道运行后自动生成覆盖项（Coverage Items），每条关联到具体需求。

### 手动添加
展开 "Add Coverage Item"：
1. 选择类型（functional / security / boundary / performance / usability）
2. 选择关联需求
3. 输入描述（如 "SQL injection in username field"）
4. 点击 "Add Coverage Item"

### 编辑 / 删除
直接在数据编辑器中修改，点击 "Save coverage edits" 保存。

---

## 6. 策略配置（Strategy 标签页）★ 核心新增

### 左侧：配置面板

#### 6.1 技术映射矩阵

| 按钮 | 功能 |
|------|------|
| **Auto-Recommend Techniques** | 根据风险等级自动推荐技术组合 |
| **Reset All** | 清空所有勾选 |

推荐规则（可配置 `recommender_rules.json`）：

| 风险等级 | 推荐技术 |
|----------|----------|
| H (High) | DecisionTable + BVA + EP |
| M (Medium) | EP + BVA |
| L (Low) | EP |

矩阵中每行代表一个需求，每列代表一种测试技术，勾选即启用：

| 技术 | 缩写 | 说明 |
|------|------|------|
| Equivalence Partitioning | EP | 等价类划分 |
| Boundary Value Analysis | BVA | 边界值分析 |
| Decision Table | DT | 决策表 |
| State Transition | ST | 状态转换（白盒） |

#### 6.2 技术参数配置

| 参数 | 默认值 | 范围 | 说明 |
|------|--------|------|------|
| BVA Offset | ±1 | ±1 ~ ±5 | 边界偏移量，±1 生成 4 条/字段，±5 生成 12 条/字段 |
| EP Valid Partitions | 1 | 1 ~ 5 | 每个范围生成的合法等价类数量 |
| EP Invalid Partitions | 2 | 1 ~ 5 | 每个范围生成的非法等价类数量 |

#### 6.3 套件快捷分配

将选中的需求快速分配到已有测试套件（需先在 Suites 标签页创建套件）。

#### 6.4 确认按钮

**"Apply Strategy & Generate Test Cases"** — 应用当前策略配置并生成测试用例。

### 右侧：实时预览

- **Estimated Test Cases** — 预计生成的用例总数（大号数字）
- **Breakdown by Technique** — 各技术预计生成数量
- **Coverage Estimation** — 按风险等级的覆盖率进度条（H/M/L）

修改策略时预览即时更新。

---

## 7. 测试套件（Suites 标签页）★ 新增

### 创建套件
1. 展开 "Create Suite"
2. 输入套件名称（如 `Security_Suite`）和描述
3. 点击 "Create Suite"

### 管理套件
- 每个套件卡片显示名称、描述、关联需求数
- 点击 "Delete" 删除套件

### 快速分配
- 多选需求 → 选择目标套件 → 点击 "Assign to Suite" / "Remove from Suite"
- 分配后生成的测试用例会自动打上套件标签（如 `#security_suite`）

---

## 8. 测试用例（Test Cases 标签页）

### 查看
管道生成的所有测试用例以表格展示，包含：ID、关联需求、标题、技术类型、优先级、步骤、测试数据、预期结果。

### 编辑
直接在数据编辑器中修改任何字段，点击 "Save test case edits" 保存。

### 按需求重新生成
选择特定需求 ID，点击 "Regenerate cases for selected requirement" 仅重新生成该需求的用例。

### Test Oracle（FR 5.0）
展开 "FR 5.0 Test Oracle"：
1. 输入测试数据（username, password）
2. 点击 "Generate expected result"
3. LLM 生成预期结果

---

## 9. 白盒测试（White-Box 标签页）

支持两种模型类型：
- **State Machine** — 状态机模型（适用于登录流程等）
- **Control Flow Graph** — 控制流图（适用于代码路径覆盖）

### 输入模式
- **Manual** — 手动输入 Mermaid 或 JSON 格式的模型定义
- **LLM Derive** — 从需求自动推导模型

### 覆盖率准则

| 模型类型 | 可用准则 |
|----------|----------|
| State Machine | state, transition |
| Control Flow Graph | statement, branch, path, condition, mcdc |

点击 "Generate Coverage Sequences" 生成覆盖序列，可勾选 "Apply optimization" 启用 Chinese Postman + Greedy 优化。

---

## 10. 可追溯性矩阵（Traceability 标签页）

### 概览矩阵
需求 → 覆盖项数 → 用例数 → 使用技术的整体视图。

### 正向追溯（Requirement → Coverage → Test Cases）
选择需求，查看其覆盖项和测试用例。

### 反向追溯（Test Case → Requirement）
选择测试用例，查看其关联的需求和步骤。

---

## 11. 证据驱动改进（Improvement 标签页）

### 无效用例管理
标记为 "invalid" 的测试用例在此列出，作为负面示例。

### 带反馈的重新生成
选择需求，点击 "Regenerate with feedback" — 将无效用例注入 LLM 提示词作为负样本，改善生成质量。

### 手动改进
点击 "Add improvement test case (manual)" 添加手动编写的改进用例。

### 审查审计日志
所有编辑操作（覆盖项、测试用例的修改）自动记录，含时间戳、旧值、新值。

---

## 12. 导出（Export 标签页）

| 格式 | 说明 |
|------|------|
| **JSON** | 完整项目导出（含需求、风险、覆盖项、策略、用例、审查记录） |
| **CSV** | 测试用例表格导出 |

### 附加功能
- **Add white-box state model（FR 4.0）** — 向项目添加白盒状态模型
- **Optimize suite by risk（FR 7.0）** — 按风险优先级优化测试套件顺序
- **Pipeline Metrics** — 显示各阶段耗时（Structure / Risk / Techniques ms）

---

## 快速上手示例

```
1. 侧边栏 → New project → 输入名称 "Login Test" → Create project
2. Import 标签 → 选 "Sample login requirements" → 点 "Import only"
3. Risk 标签 → 点 "Assess risks"
4. Strategy 标签 → 点 "Auto-Recommend Techniques" → 查看右侧预览
5. Strategy 标签 → 点 "Apply Strategy & Generate Test Cases"
6. Test Cases 标签 → 查看生成的测试用例
7. Export 标签 → 下载 JSON / CSV
```

---

## 技术架构

```
Streamlit UI (8501) → Core Pipeline → LLM Client (DeepSeek API)
                           ↓
                    Pydantic Models → JSON Persistence
                           ↓
                    Test Runner → Target App (Flask :5000)
```

- **LLM 模式：** 设置 API Key 后自动启用，生成质量更高
- **规则回退：** 无 API Key 时使用内置规则引擎，保证可运行
- **持久化：** 所有项目数据自动保存到 `data/projects/`，支持加载继续编辑
