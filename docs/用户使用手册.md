# AutoTestDesign 用户使用手册

---

## 一、先分清两个「Web」

| 应用 | 地址 | 作用 |
|------|------|------|
| **AutoTestDesign 工具** | http://localhost:8501 | AI 测试**设计**工具：导入需求、生成用例、审查、导出 |
| **登录模块（被测系统）** | http://127.0.0.1:5000 | **目标应用**：用来执行测试、写报告，不是工具本身 |

启动命令（两个终端都要 `conda activate autotestdesign`）：

```powershell
# 终端 1：测试设计工具
streamlit run autotestdesign/ui/streamlit_app.py

# 终端 2：被测登录页（执行测试时用）
python target-app/app.py
```

## 二、Import 页：需求文本怎么写？

Import 页大文本框支持三种写法，下面任选一种即可。侧边栏需先 **Create project** 创建项目。

### 写法 1：CSV（推荐，与示例文件一致）

**第一行必须是表头**，常用列名：

- 最少：`id,text`
- 也可：`id,title,text`（`title` 可选）

**注意：**

- 英文逗号分隔；若需求正文里含逗号，请用引号包住该字段，或改用「写法 2」。
- `id` 建议用 `REQ-001`、`REQ-002` 这种稳定编号，便于报告追溯。
- `Format hint` 选 **csv** 或 **auto**。

**示例（可直接复制进文本框）：**

```csv
id,text
REQ-001,系统应接受长度为 3 到 20 个字符的用户名
REQ-002,系统应接受长度为 8 到 32 个字符的密码，且至少包含一个数字
REQ-003,用户名为空时应显示错误信息：username is required
REQ-004,密码为空时应显示错误信息：password is required
REQ-005,正确凭据 user01 与 Pass1234 应跳转到成功页面
REQ-006,错误凭据应显示 invalid credentials
REQ-007,连续三次登录失败后账户应锁定 30 秒
```

**英文版（与内置 Sample 一致，对应 `sample_data/login_requirements.csv`）：**

```csv
id,text
REQ-001,The system shall accept username between 3 and 20 characters
REQ-002,The system shall accept password between 8 and 32 characters with at least one digit
REQ-003,Empty username shall show error message username is required
REQ-004,Empty password shall show error message password is required
REQ-005,Valid credentials user01 and Pass1234 shall redirect to success page
REQ-006,Invalid credentials shall show error invalid credentials
REQ-007,After three failed login attempts the account shall be locked for 30 seconds
```

### 写法 2：简化 CSV（无表头，每行一条）

与内置 **Sample login requirements** 相同：每行 `编号,需求正文`，**不要**写 `id,text` 表头。

`Format hint` 选 **auto**（会根据逗号和 `REQ` 字样尝试按 CSV 解析）。

```text
REQ-001,The system shall accept username between 3 and 20 characters
REQ-002,The system shall accept password between 8 and 32 characters with at least one digit
REQ-003,Empty username shall show error message username is required
```

### 写法 3：纯文本（一行一条需求）

每行一条完整需求；`Format hint` 选 **text** 或 **auto**。

**带编号（推荐）：**

```text
REQ-001: 用户名长度必须在 3 到 20 个字符之间
REQ-002: 密码长度必须在 8 到 32 个字符之间，且至少包含一个数字
REQ-003: 用户名为空时显示 username is required
```

**不带编号（系统自动生成 ID）：**

```text
用户名长度必须在 3 到 20 个字符之间
密码长度必须在 8 到 32 个字符之间，且至少包含一个数字
登录成功应跳转到 success 页面
```

支持的编号格式示例：`REQ-001`、`REQ_001`、`R1`、`1.`、`1)` 等。

## 三、需求怎么写效果更好？

工具会做结构化、风险分析和黑盒用例生成。写得越具体，生成结果越贴近你的系统。

| 建议写清楚 | 示例 |
|------------|------|
| 字段名 | username、password |
| 数值范围 | 3–20 字符、8–32 字符 |
| 规则 | 至少 1 个数字、连续失败 3 次 |
| 预期结果 | 显示某错误文案、跳转 success、锁定 30 秒 |
| 有效测试数据 | user01 / Pass1234（与被测应用一致） |

**与被测登录应用 `target-app` 的对应关系：**

| 需求主题 | 被测应用行为 |
|----------|----------------|
| 用户名 3–20 | 否则提示 invalid username |
| 密码 8–32 且含数字 | 否则提示 invalid password |
| 空用户名/密码 | username/password is required |
| user01 + Pass1234 | 跳转 `/success` |
| 其他组合 | invalid credentials |
| 连续 3 次错误 | 锁定约 30 秒 |

若你改被测应用规则，请同步修改需求文本，否则生成的用例会与执行结果不一致。

## 四、Import 页三个按钮

| 按钮 | 作用 |
|------|------|
| **Import only** | 仅 FR 1.0：解析文本为需求列表，不做 AI 结构化 |
| **Import + Structure** | FR 1.0 + 1.1：导入并结构化（输入、范围、条件、预期） |
| **Run full pipeline** | 一键：导入 → 结构化 → 风险 → 三种黑盒用例（EP/BVA/判定表） |

点击上述按钮后，页面会展开 **状态面板**（英文提示）、**进度条**和等待说明（LLM 约 10–60 秒 / 规则引擎通常数秒），完成后有 **Toast** 与 “Last operation” 绿色摘要，避免误以为卡住。

首次使用建议：**Paste** 粘贴上文 CSV → **Run full pipeline** → 下方表格出现结构化字段即成功。

**Source 选项：**

- **Paste**：使用你自己填写的大文本框。
- **Sample login requirements**：自动填入登录模块 7 条英文需求（演示用）。

## 五、各标签页功能说明

### 1. Import（导入）

见第二节；作业演示主线起点。

### 2. Risk（风险 FR 2.0）

- 点击 **Assess risks** 为每条需求生成 0–100 分、优先级 **H/M/L** 及理由。
- 用于撰写 `docs/risk-analysis.md`。

### 3. Coverage（覆盖项 · 交互审查）

- **Generate test cases** 若尚未生成用例，在此触发 FR 3.0。
- 表格可增删改 **覆盖项**；**Save coverage edits** 保存并记入审查日志。

### 4. Strategy（测试策略）

- 记录采用的测试技术（EP、BVA、DecisionTable）及选用理由。
- 可编辑；作业「覆盖策略与方法」对应此页。

### 5. Test Cases（测试用例 · 交互审查）

- 查看/编辑用例：步骤、预期结果、优先级等。
- **Regenerate cases for selected requirement**：仅对某条需求重新生成用例。
- **FR 5.0 Test Oracle**：输入 username/password，按规则生成预期结果（预言）。

### 6. Traceability（可追溯矩阵）

- 展示每条需求关联的覆盖项数量、用例数量、使用的技术。
- 用于报告中的需求–用例追溯表。

### 7. Improvement（证据改进）

- 显示 **ReviewEvent**（你对覆盖项/用例的修改记录）。
- **Add improvement test case**：演示「基于证据补充用例」（如会话超时）。

### 8. Export（导出 FR 6.0）

- **Download JSON**：完整项目（需求、风险、用例、审查记录）。
- **Download CSV**：扁平测试用例表，可导入 Excel 或测试管理工具。
- 可选：**Add white-box state model（FR 4.0）**、**Optimize suite by risk（FR 7.0）**。
- 显示各阶段耗时（毫秒），用于 NFR 性能说明。

## 六、侧边栏

| 功能 | 说明 |
|------|------|
| **LLM enabled / Rule-based fallback** | 见下文「LLM 是否默认」；侧边栏绿字=走 API，黄字=规则引擎 |
| **Open project / Load project** | 打开已保存项目（数据在 `data/projects/*.json`） |
| **New project** | 填写项目名称、目标应用描述后创建 |

### LLM 是否默认开启？

| 条件 | 实际行为 |
|------|----------|
| **未配置** `OPENAI_API_KEY`（或 `.env` 不存在） | **默认：规则引擎**，不调用任何大模型 API |
| **已配置** 有效 `OPENAI_API_KEY` | 结构化、风险、EP/BVA/判定表等步骤优先调用 LLM + `prompts/` 模板 |

`.env` 示例（项目根目录，复制自 `.env.example`）：

```env
OPENAI_API_KEY=你的密钥
OPENAI_MODEL=gpt-4o-mini
TARGET_APP_URL=http://127.0.0.1:5000
```

将 `OPENAI_API_KEY` 留空或删掉该行 → 与「不配置」等价，仍为规则模式。

## 七、被测登录应用使用说明

访问 http://127.0.0.1:5000 ：

| 输入 | 结果 |
|------|------|
| 空用户名 | username is required |
| 空密码 | password is required |
| 用户名长度 &lt;3 或 &gt;20 | invalid username |
| 密码不合规 | invalid password |
| user01 + Pass1234 | 进入成功页 |
| usr + Pass1234 | 也可登录（边界演示账号） |
| 其他组合 | invalid credentials |
| 同一浏览器连续 3 次错误密码 | 账户锁定约 30 秒 |

测试重置（自动化测试用）：http://127.0.0.1:5000/reset

## 八、推荐完整操作流程（演示）

1. `conda activate autotestdesign`
2. 启动 Streamlit → 侧边栏 **Create project**
3. **Import** → 粘贴 CSV 需求 → **Run full pipeline**
4. 查看 **Risk**、**Coverage**、**Test Cases**、**Traceability**
5. 在 **Test Cases** 或 **Coverage** 中修改一条记录 → **Save** → **Improvement** 查看审查日志
6. **Export** 下载 CSV/JSON
7. 启动 `target-app` → 浏览器手工验证 2～3 条用例
8. 运行自动化：`pytest target-app-tests/test_login_client.py autotestdesign/tests -v`

## 九、常见问题

**Q：粘贴后显示 0 条需求？**  
- 检查是否为空行-only；CSV 是否缺少 `text` 列；`Format hint` 是否与格式匹配（纯文本请选 text）。

**Q：LLM 是默认使用的吗？**  
- **不是。** 只有项目根目录 `.env` 里配置了有效的 `OPENAI_API_KEY` 时才会调用大模型；未配置或留空时，全程使用内置**规则引擎**（关键词、边界模板、登录判定表等），不联网也能跑通演示。  
- 侧边栏：**LLM enabled**（绿色）= 当前走 API；**Rule-based fallback**（黄色）= 当前走规则。  
- 作业上工具仍是「AI 驱动」：提示词在 `autotestdesign/prompts/`，配置 Key 后即按 prompt 调用 LLM；未配置时用规则保证可复现、满足 FR。

**Q：中文需求可以吗？**  
- 可以。两种模式都支持中文需求文本。配置 LLM 后，结构化与自然语言理解通常更灵活；仅用规则时，请尽量写清字段名、数字范围和预期错误文案（见第三节）。

**Q：生成用例很多，是否正常？**  
- 三条需求 × 三种技术会产生较多用例；可用 FR 7.0 优化排序，或在报告中说明高优先级子集。

**Q：与 pytest 关系？**  
- 工具**设计**用例；`target-app-tests/` **执行**用例。不必在 Streamlit 里点「运行测试」。
